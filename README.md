# Poki Career OS: Phase 0 backend

Security-hardening fork of [shanebe-ai/letsmcp](https://github.com/shanebe-ai/letsmcp), paired with [p0ki/JobOS](https://github.com/p0ki/JobOS). Upstream history and MIT attribution are preserved. All changes belong to `security/phase-0-hardening`; do not deploy or merge without explicit approval.

## Supported security boundary

One local owner, one Linux process, Node 24 LTS. HTTP listens only on loopback. Every business API requires an opaque application session. Local owner sign-in is disabled until a 32+ character passphrase is configured; no default/password file is generated by the application. This is a local bootstrap bridge for later verified OAuth, not public user enrollment.

MCP runs on stdio, whose access boundary is the trusted launching process. There is no unauthenticated HTTP `tools/call` transport. Arbitrary command execution and browser scraping are disabled, including direct legacy calls. Filesystem tools and HTTP data use an explicit private SAFE_DATA_DIR with canonical path, no-follow file-descriptor confinement and size/entry limits. Public fetch validates all DNS answers, pins its connection and revalidates every redirect.

## Safe local setup

1. Install locked dependencies: `npm ci --ignore-scripts`.
2. Create a new empty, private directory outside the repository for **synthetic fixtures only**; it must be owned by your user, mode 0700, absolute and without symlink ancestors.
3. Copy `.env.example` to ignored `.env`. Set `SAFE_DATA_DIR` to that directory and `POKI_BOOTSTRAP_PASSWORD` to a locally generated random 32+ character passphrase. Never commit it. Keep `POKI_ENABLE_AI=false` and provider keys empty. No real credentials or personal data are needed for tests.
4. `npm run build` then `npm start` starts the local API at `127.0.0.1:3002` and stdio MCP. Open the paired frontend at `http://127.0.0.1:8080`. The exact APP_ORIGIN must match; mutating HTTP requests require its Origin header.

Health is public but exposes no provider configuration or private data. Business requests use the app cookie, not browser identity/ID-token claims. Runtime provider config is always forbidden. AI remains off by default and selected-provider-only when explicitly enabled; no AI request was made during this audit.
